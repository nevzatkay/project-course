My interpretation of the brief

My interpretation of the research project is that the main goal is to build a structured data warehouse for League of Legends match data, where match information, player performance, champions, teams, objectives and other relevant game statistics can be collected, stored and analysed efficiently.

The project should not focus only on collecting match data, but also on designing a reliable data model that makes it possible to analyse matches from different perspectives. This could include player and champion performance, team performance, game duration, objectives, item builds, win rates and relationships between different match variables.

I see the project as a combination of data engineering, database design and data analysis, with an emphasis on creating a system that can handle a large amount of historical match data and make it useful for further analysis.

Why I am a good fit for this project

This project is especially relevant to me because I am interested in software development, databases and data processing. I also have experience working with backend systems and structured data, which I believe would be useful for designing and implementing the data warehouse.

I am interested in the complete process, from collecting and cleaning the match data to designing the database structure, implementing the ETL pipeline and creating analytical queries. I would also like to explore how the collected data can be used to identify meaningful patterns in player, champion and team performance.

Proposed approach

I would first investigate the available League of Legends match data sources and determine which data can be collected reliably and legally. Based on the available data, I would define the main entities and relationships required for the warehouse.

The initial data model could include matches, players, teams, champions, roles, items, objectives and performance statistics. I would then design a suitable relational or dimensional warehouse structure depending on the requirements of the project.

After designing the schema, I would implement an ETL pipeline that collects the raw match data, validates and cleans it, transforms it into the required structure and loads it into the data warehouse.

I would then create analytical queries and views that can be used to investigate different aspects of the matches. For example, the system could be used to analyse champion performance, player statistics, team performance, objective control, game duration and relationships between different match characteristics.

Another part of the project would be evaluating the performance and reliability of the data warehouse. I would examine issues such as duplicate records, missing data, inconsistent values and the scalability of the system when the number of stored matches increases.

If suitable data is available, I would also like to create a visualisation layer to make the collected information easier to explore and compare.

Initial plan

* Populate the warehouse with historical match data.
* Develop analytical queries for players, champions, teams, objectives and match performance.
* Evaluate data quality, consistency and possible scalability issues.
* Create visualisations or dashboards for selected analyses.
* Document the architecture, implementation and results.
* If the results and scope are suitable, prepare the project for TDK.
