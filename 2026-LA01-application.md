My interpretation of the brief

My interpretation of this project is to design and implement a relational database for an electric vehicle charging network and then investigate how the database can be optimized when working with a large amount of data.

The system would contain information about charging stations, charging points, users, vehicles, reservations, charging sessions, energy consumption, tariffs, payments and technical events. The main focus, in my understanding, is not developing a complete charging application, but building a well-designed database and investigating how its structure, indexes and SQL queries affect performance.

I am particularly interested in the performance optimization part of the project. I would like to see how different indexing strategies and query modifications affect execution time and execution plans when the database contains a large amount of realistic data. I also find the comparison between traditional database optimization and suggestions generated by an AI service interesting, especially when the suggestions have to be tested rather than simply accepted.

Why I am a good fit for this project

This project is a good match for me because I am interested in databases, backend development and performance optimization. I have previously worked on software projects where structured data, persistence and backend architecture were important parts of the system.

I would like to improve my database knowledge further by working with a larger and more realistic database and by focusing on performance rather than only basic CRUD operations.

I am also interested in understanding why a particular query is slow, how the database engine processes it and how an appropriate index or query modification can change the execution plan. I think this practical approach would give me useful experience beyond simply designing a database schema.

Proposed approach

I would first design the data model based on the real processes of an electric vehicle charging network. I would define the main entities and relationships and make sure that keys, constraints and referential integrity are properly handled at the database level.

After implementing the initial schema, I would create a reproducible test-data generation process. The goal would be to generate a sufficiently large dataset, including at least 100,000 charging sessions and more than one million measurement or status records, so that performance differences can be observed realistically.

I would then create several complex SQL queries representing different operational and business scenarios. These would include joins, aggregations, time-based searches, subqueries or CTEs and window functions.

For selected queries, I would record their initial execution plans and runtime characteristics. I would then investigate different optimization approaches, such as simple and composite indexes and database-specific indexing features depending on whether Oracle or Microsoft SQL Server is selected.

After each optimization, I would repeat the measurements and compare the results. I would focus not only on whether a query became faster, but also on understanding why the execution plan changed and whether the optimization remains useful with different amounts of data.

As part of the AI-related requirement, I would provide selected queries to an AI service and collect its optimization or indexing suggestions. I would then review the suggestions manually and test the applicable ones against my own solutions. This would allow me to compare the suggestions based on correctness, executability and actual measured performance rather than assuming that an AI-generated solution is automatically better.

Initial plan

* Define the main business processes and requirements of the charging network.
* Design the relational data model with at least ten related tables.
* Define primary keys, foreign keys, constraints and other important business rules.
* Implement the database using Oracle Database or Microsoft SQL Server.
* Create a reproducible test-data generation process.
* Populate the database with at least 100,000 charging sessions and at least one million measurement or status records.
* Develop complex SQL queries representing realistic operational and business tasks.
* Implement at least one stored procedure or function for business logic.
* Identify queries with potential performance problems and record their initial execution plans and runtimes.
* Design and test different indexing and query optimization approaches.
* Compare the results before and after optimization using execution plans and measured performance.
* Develop a script or application component that can automatically repeat the performance measurements.
* Collect optimization suggestions from an AI service for selected queries and compare them with my own approaches.
* Document the limitations and security considerations of using an external AI service.
* Document the database design, experiments, measurements and conclusions.
* If the results are suitable, prepare the work for TDK.

Additional information

I plan to maintain the project in a Git repository from the beginning and use issues to organise the database design, implementation, experiments and optimization tasks.

I would like to keep the development process reproducible, so the database scripts, test-data generation, SQL queries and performance measurement tools would all be maintained as part of the project.

Depending on the selected database system, I would use the appropriate native performance analysis tools, such as EXPLAIN PLAN and DBMS_XPLAN for Oracle or execution plans together with SET STATISTICS IO and SET STATISTICS TIME for Microsoft SQL Server.

My main goal would be to build a realistic database and then use measurable results to understand and demonstrate how database design and optimization decisions affect performance.
